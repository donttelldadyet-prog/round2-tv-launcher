# Guest messages

Merged into `main` on 29 Oct 2026 (it was built on the `feature/guest-messages` branch). Live on GitHub Pages with the control centre.

Guests write their own birthday, anniversary, celebration or note message for the room TV. It works for bookings from any channel (WhatsApp, Telegram, TikTok, SimplyBook, walk-in), because staff send a link instead of the guest messaging a bot.

## How it works

1. **Staff make a link after the booking is paid.** On the staff page, pick the room, date and start time; there's no end time. Make creates an 8-character random code tied to that room and start.
2. **Staff paste the invite into whatever chat the guest booked in.** Link: `https://donttelldadyet-prog.github.io/round2-tv-launcher/msg/?c=CODE` (live once merged).
3. **The guest writes the message.** The room can't be changed. The show time is a button: start, +15, +30, +45 or +60 min. Make re-checks all of this. After sending, the guest sees a confirmation screen with the card as it will look, and can change it until it pops up.
4. **Approved automatically.** Staff don't approve anything. They can Cancel anything they don't like (this also takes it off the TV), or Change time.
5. **Sent to the TV just before its time.** Each TV holds one message at a time (`/r2/<key>/<room>/msg`), so a message sent days early could be replaced by any other. The timer checks every 15 minutes from 10:30am to 5:15am (SG) and sends each message due within the next 16 minutes, earliest first. A message due sooner than that, or one staff press **Send to TV now** on, goes straight away.
   **TV slot rule (the `push` action):** before writing, it reads what's on the TV. If an *earlier* message is on the TV (waiting or still showing, not expired), it answers straight away, then waits (Make Repeater + Sleep) until a minute before its own time (and at least a minute after the earlier one shows), checks it wasn't cancelled or moved, and writes. If a *later* one is waiting, it writes and puts that one back in the queue (`onTv` = `no`). So Time's up + "10 minutes left" both show, and a guest message and a Round2 message close together don't wipe each other.
6. **Cut-off.** Behind the scenes, `end` = start + 3 h. The link closes then, and the TV stops showing the message (`until`), so it can't pop up for the next group. Nobody types an end time.
   ⚠ Booking times: a SimplyBook booking's `end_date` includes 15 min cleaning (11:00–14:15 for a 3 h session). Anything about the guest's end ("10 minutes left", "That's a wrap", when messages stop) uses the **guest end = end_date − 15 min**, never the SimplyBook end. See docs/booking-times.md.
7. **Change time or room** (late, rescheduled or changing rooms): staff set a new room and start. The message's show time moves by the same amount and gets a new id, so the TV shows it again. If it had already been sent to the TV, it's taken off and re-sent at the new time.

One webhook; `action` decides the route. The pages POST form-encoded fields, so there's no CORS preflight.

| action | who | needs | does |
| --- | --- | --- | --- |
| `create` | staff | `staff`, `room`, `start` (ms), `label` | new code; `end` = start + 3 h |
| `get` | guest | `code` | the link record; refuses unknown, cancelled, finished |
| `submit` | guest | `code`, `kind`, `to`, `from`, `title`, `text`, `at` | saves and approves; refuses times outside the first hour, unknown occasion, empty headline, text over 600, names over 40, and edits once the show time has passed. If due within 16 min, sends it to the TV now. |
| `list` | staff | `staff` | links that finished less than 2 days ago or later. Make answers plain `Accepted` when there are none. |
| `move` | staff | `staff`, `code`, `start`, `room` | new start and room (upgrades, room swaps); the show time keeps the same gap after the start, and the message is taken off the old room's TV if it was there |
| `now` | staff | `staff`, `code` | show time = now, send to the TV |
| `cancel` | staff | `staff`, `code` | closes the link; takes the message off the TV if it's still the one there |
| `r2` | control centre | `staff`, `room`, `kind`, `to`, `from`, `title`, `text`, `ack` (`yes`/`no`), `at` | queues a Round2 "At a set time" message. Key `R2` + 6 characters, `label` = `Round2`, `id` starts `q`. Any of the 7 kinds (incl. `volume`, `wrapup`, `timeup`). Cancel, move and now work on it like a guest link. |
| `push` | internal | `staff`, `code` | writes the record to the room's TV, sets `onTv` = `yes`. Called by the scenario itself and by the timer. |

Records hold exactly the TV message fields (`id`, `kind`, `to`, `from`, `title`, `text`, `ack`, `at`, `until`) plus link fields (`room`, `start`, `end`, `status`, `label`, `onTv`, timestamps). Sending to the TV sends the whole record; the TV ignores fields it doesn't use.

The staff code is not in this repo. It's in the ROUND2 HOMESCREEN Project notes.

### Make gotchas found while building

- `datastore:GetRecord` must have `returnWrapped` set, or the run fails with a vague `BundleValidationError`.
- Mapping a whole bundle (`{{20}}`) into Transform to JSON gives the literal `20`. Use `returnWrapped: true` and map `{{20.data}}`.
- `replace(x; /\s+/g; " ")` didn't behave as a regex here (it spaced out every letter). Use `replace(x; newline; " ")`.
- `datastore:UpdateRecord` defaults to `upsert: true`, which would let a made-up code create a record. It's set to `false`.
- A field that isn't in the data structure is silently dropped, and a number `0` didn't save. That's why "sent to the TV" is a text field, `onTv` = `yes`/`no`.
- The TV database refuses rooms it doesn't know (`401 Permission denied`). That's useful for testing: a record with room `zzz-test` exercises every step without touching a real TV.

## Front door (Cloudflare, since 30 Oct 2026)

Every page (guest page `manager/msg/`, staff page `manager/msg/staff.html`, control centre Messages + calendar) POSTs the same
form fields to **`https://round2-book.donttelldadyet.workers.dev/gm`** instead of the Make webhook. The booking engine
(round2sg-home `worker/round2-book.js`, function `gm`) then:

- **Staff actions** (`create`, `list`, `move`, `now`, `cancel`, `r2`, `push`): checks the staff code itself (secret `GM_STAFF`), so
  wrong guesses never reach Make, then passes the request through unchanged and returns Make's answer.
- **Guest `get`**: answers from a 1-minute cache of the link (reloads cost nothing); unknown codes are cached for 5 minutes.
- **Guest `submit`**: checks it like Make does (occasion, headline, 600 characters, show time = start … +60 min in 15-min steps,
  not after it popped up, not cancelled), answers `{ok, unchanged}` without calling Make when nothing changed, and allows
  **8 changes per link** (then "message Round2").
- **Staff `list`** is answered from memory for 15 minutes and fetched from Make again only after a change went through the front door (staff action or guest save). The staff page used to poll Make every 30 s while open: that alone used ~5,000 operations in a day (30 Oct).
- **Rate limit** per visitor (IP): 30 guest calls / 10 min, 200 staff calls / 10 min.
- Cache, edit counts and rate limit live in the engine's Durable Object (`HoldBook`, tables `gm` and `gmrate`).
- The guest page keeps **Send** greyed out ("Saved ✓") until something actually changed.

The Make webhook address the engine uses comes from the Cloudflare secret `GM_HOOK_URL` (set 30 Oct; the old public webhook 4000032 is deleted). The Make scenarios still re-check everything; the front door only saves operations.

## Timer (Cloudflare, since 30 Oct 2026)

The booking engine's Durable Object keeps the queue (table `gmq`: code, room, show time `at`, end, pushed) and wakes itself
with a Durable Object alarm **one minute before each message's time**, then calls Make's `push` for it (same as the old timer,
so the TV slot rule still applies). Make only runs when a message actually goes out – no more runs every 15 minutes.

- The queue is rebuilt from Make's `list` whenever the engine reads it (staff list, any staff change) and at least once a day.
- Guest saves and the booking page's celebration messages are added straight away.
- After pushing a message, later messages for the same room go again at their own time (the TV holds one message; `push`
  may have put a later one back in the queue).
- Check it: POST `/gm` with `action=queue&staff=<staff code>` (add `sync=1` to rebuild from Make first) → `{queue:[…]}`.
- Messages now reach the TV ~1 minute before their time instead of up to 15 minutes before, so a TV with a wrong clock can show
  them at most about a minute early.

## Follows the booking (Cloudflare, since 30 Oct 2026)

Each guest link (not Round2's own `R2…` messages) is tied to the SimplyBook booking in **the same room starting at exactly
the link's start time**. SimplyBook tells the booking engine (`round2sg-home` `worker/round2-book.js`, HoldBook table `gml`)
the moment a booking is made, changed or cancelled (its callback URL points at the engine's `/sb/notify/<key>`, which passes
it on to Make's mirror-rooms scenario unchanged). The engine also checks right before a message goes to its TV, and every
6 hours as a backstop:

- **Booking moved** (new time, new day or new room): the link moves with it (Make `move`, so the show time keeps the same
  gap after the start and the TV is updated).
- **Booking cancelled:** the link is cancelled. Exception: if the same guest has exactly one other upcoming booking
  (cancel-and-rebook), the link moves to that one instead.
- **Staff move a link by hand:** the engine lets go of it (never fights a manual change) and only ties it again if a
  booking starts exactly at the new room + time.
- **No booking at that room + time** (e.g. the link was made for a slightly different time): nothing happens; staff move it
  by hand as before.
- **Online bookings** (booking page "Celebrating?"): the message is tied to its booking the moment it's made (31 Oct).
- **Booking cancelled before the engine tied it** (no booking left at that room + start, but a cancelled one is there):
  the link is cancelled too (31 Oct; this left two test messages behind on 30 Oct).
- **Another guest takes the slot** of a cancelled booking before the link was tied: the engine compares when the link and
  each booking were made (SimplyBook `record_date`). Cancelled booking made before the link + live booking made after it →
  the message belonged to the cancelled guest → cancelled, never shown to the new guest.
- Safety: more than 3 cancels in one check → nothing is cancelled (logged as "held"), in case SimplyBook answers oddly.

Costs: one SimplyBook read per booking change (120 days of bookings); Make only when a message actually moves. Staff can see the
list and the last 30 changes with `/gm` `action=queue` (fields `follow`, `followLog`) and run a check with `action=follow`
(`dry=1` shows what it would do). The engine's `/status?deep=1` shows counts only (no codes): `follow.links`, `bound`,
`last`, `check.would`.

## Cut-off for session-end messages (31 Oct 2026)
"That's a wrap!" (`timeup`) stops showing **15 minutes** after its show time (the cleaning time), and "About 10 minutes to
go" (`wrapup`) after **4 minutes**, so it shows **once**: OK or Back and it doesn't come back (a repeat 5 minutes later would
still say "10 minutes"; owner, 31 Oct). Neither can pop up for the next group if nobody pressed
OK. All other messages keep the 3-hour cut-off. Set in Make (`r2` route and `move` route: `end`/`until`) and in the
control centre (Messages: send now, send again).

## Big banner vs small banner (owner's terms and rules, 31 Oct 2026 – use these words)
- **Big banner** = the message card on the Round2 Home screen (menu in front).
- **Small banner** = the message card over another app or input (PlayStation/HDMI, Netflix, YouTube…): Android's overlay
  card (`FoodAlerts.java` `showMsgPage`), the rooted LGs' Round2 Alerts card (`webos/alerts`), or LG's own pop-up if
  Round2 Alerts can't open.

Rule (owner): **"must be acknowledged" means the guest has to press OK. It never disappears on its own** (big or small
banner); Back and every other button only shake it. Only the cut-off removes it.

| | Big banner | Small banner |
|---|---|---|
| Must be acknowledged | Stays until **OK**; Back/other buttons shake it | Stays until **OK**; Back/other buttons shake it |
| OK not needed | Shows **1 min**, then gone | Shows **45 s** once, then gone |
| Guest leaves the home screen while one is waiting | – | Becomes a small banner straight away |
| Guest goes back to the home screen while one is waiting | Shown as a big banner right away | – |
| TV switched on while one is waiting | Shown as soon as the TV is on | Shown as soon as the TV is on |
| Home screen still loading (after standby / a long film) | Held and shown as the big banner once loaded (never a small banner over our own home screen) | – |

Which messages need OK: guest messages always; Round2 birthday/note/anniversary, "About 10 minutes to go", "That's a
wrap!" by default; volume reminder and the others: staff choose (tickbox).

Cut-off (gone for good, OK or not): guest message = booking start + 3 h · Round2 message = show time + 3 h ·
"That's a wrap!" = +15 min · "About 10 minutes to go" = +4 min · Test bench = 1 h.
One message per TV: a newer one replaces the one showing, **except** that a Round2 message (e.g. "That's a wrap!") waits
while a guest message is on the TV and not yet acknowledged (engine timer, checks every 2 min; dropped at its own cut-off).
Staff "send now" from the control centre is not held.

**Same rules on Android and LG** (owner, 31 Oct): LG's Round2 Alerts card writes `card.up` ("msg <id>" / "food <no>",
refreshed every minute) so the helper never re-pops or re-chimes a card that's still up; Android checks its own card.

**Food alerts** (same banner words): "Order locked in" = 20 s, then gone (big and small banner, Android and LG).
"Loot dropped" = **stays until OK** everywhere (owner: "it lets us know they know"); if it isn't on screen (TV was off…)
it comes back every 5 minutes until OK. Loot dropped comes first: a waiting message shows after it's OK'd.

**Show again at…** (staff page, a message that's already been on the TV): pick a time (5-min steps, until the message's
cut-off, max 6 h ahead); the booking engine sends it to the TV again then (`/gm` `action=later`, table `later`), needing
OK again. "Don't show again at …" clears it.

## In session (control centre, 31 Oct 2026)

For the admin who handles extensions. Control centre › **In session** (engine `POST /gm` with the staff code: `action=insess`, `extend`, `extundo`; round2sg-home `worker/round2-book.js` "In session").

- **Reads** today's SimplyBook bookings and time-blocked notes per room (a WhatsApp booking may be a note). EXT notes that start where a session ends are stacked onto it. Mirror blocks (the Make mirror's SYSTEM BLOCK bookings, clients 2472/2476, or anything named SYSTEM BLOCK) are never shown as sessions; Atlas/Vale say "Via Vale/Atlas" instead. Notes longer than 12 h (a room closed for months) only count as clashes.
- **+1h / +2h / +3h** (always as EXT notes, owner's rule): 1-hour time-blocked notes from the session's SimplyBook end (each hour includes the 15-min cleaning), note text `EXT +1h (1/2) · <guest> · control centre`. Vale and Atlas: the twin gets the same notes as `SYSTEM BLOCK · EXT +1h for <room> · <guest>`.
- **Clash check** first (other bookings/notes in the room or its twin, past 11:15pm closing); the review box shows exactly what will change and only "Extend anyway" goes past a clash. If the session changed since the page loaded, the engine refuses (no double extensions).
- **Messages**: "About 10 minutes to go" moves to new end − 10 min and "That's a wrap!" to the new end (Make `move`); if a room had none, they're created (Make `r2`). Found by kind, same room, within 20 min of the old end.
- **TV banner** (Firebase `msg`, written by the engine): `kind: "extend"`, title `+N CREDIT(S) ADDED`, text `Your session has been extended by N hour(s).`, `n`, `ack` = the card's "Banner needs OK" tick (default off: big banner 1 min, small banner 45 s, like any no-OK message). Not written if a guest message is on the TV and not OK'd yet. Coin-into-slot animation on the home screen (web), Android over apps (FoodAlerts) and LG over apps (alerts app); tag "SESSION EXTENDED".
- **Undo** (30 min): deletes the notes, moves the messages back / cancels the ones it made, removes the banner if still up.
- **Test** button: banner only (marked TEST) on a TV you pick. Nothing else changes.
- Tested 31 Oct on 1 Jun 2027 with a test note in Vale: notes in Vale + SYSTEM BLOCK in Atlas, chain read back, clash with a blocker in Atlas found, undo removed all four notes.

## Switching apps while a banner is up (31 Oct 2026)

- **Android:** the small banner is a system overlay, so it stays on top when the guest jumps YouTube → Netflix with the remote's Netflix button (or the TV ignores that button while the card has the remote – it shakes, like any other button). Pressing Home brings the message straight back as the big banner (`FoodAlerts.menuInFront`).
- **LG:** webOS may close the Round2 Alerts card when another app opens. The helper (`watch_apps`) checks 2 s after any app-to-app switch whether `sg.round2.alerts` is still running; if not, it clears `card.up`/`msg.last`/`food.last` so a message waiting for OK, or Loot dropped, pops up again over the new app within seconds. Home pressed while the card was up: `card.up` is cleared and the big banner shows straight away.
- No-OK messages and Order locked in are not brought back (they were already shown once).
